# Tech Interview 2: Fix the AI's Mistakes

## Overview

This exercise contains AI-generated code for a Marketing Document Processor that uses LLM integration. The code has several bugs and anti-patterns that you need to identify and fix.

## Quick Start

Download the provided zip file, unzip it, and open the directory in your editor.

### Option A: Docker Compose (recommended)

```bash
# Start both services
docker-compose up -d

# Wait for services to be healthy (about 10 seconds)
docker-compose ps

# Enter the exercise container
docker-compose exec exercise bash

# Test that the mock LLM server is working
curl http://mock-llm:8080/health
```

### Option B: Manual Setup (no Docker required)

Requires **Python 3.11+**.

**Terminal 1 — start the mock LLM server:**

```bash
pip install -r requirements-mock.txt
python mock_llm_server.py
```

The server will start on `http://localhost:8080`. Leave this terminal running.

**Terminal 2 — set up the exercise environment:**

```bash
pip install -r requirements.txt

export LLM_API_BASE=http://localhost:8080
export LLM_API_KEY=mock-key-not-needed

# Verify the mock LLM server is reachable
curl http://localhost:8080/health
```

All commands in the **Running the Code** section below should be run from Terminal 2.

## Your Task

The file `processor.py` was generated by an AI assistant to process marketing documents (campaign briefs, budget notices, etc.) using an LLM to extract structured data.

**The code has multiple bugs and anti-patterns.** Your task is to:

1. **Review** the code carefully
2. **Identify** the bugs and anti-patterns
3. **Explain** why each is problematic
4. **Fix** the issues
5. **Verify** your fixes work

## Environment

- Python 3.11 with asyncio
- A mock LLM server simulates OpenAI's chat completions API
  - Option A (Docker): reachable at `http://mock-llm:8080`
  - Option B (manual): reachable at `http://localhost:8080`
  - No real API key needed (use any string)
  - Will return rate limit errors after too many concurrent requests (by design!)
- Sample marketing documents are provided in `test_documents.py`

## Running the Code

```bash
# Option A: enter the container first, then run commands from the shell inside it
docker-compose exec exercise bash
# The container keeps running between commands — use exec each time you re-enter

# Run the processor (will show bugs in action)
python run_processor.py

# Run tests to verify your fixes
pytest tests/ -v

# Run with verbose output to see what's happening
python run_processor.py --verbose
```

> **Note:** Use `docker-compose exec`, not `docker-compose run`. `run` creates a
> temporary container that exits when the command finishes; `exec` runs inside the
> already-running container, which stays up regardless of exit codes.

## Hints

Consider these areas when reviewing:

- **Resource management** - Are connections/sessions handled properly?
- **Error handling** - What happens when things go wrong?
- **Concurrency** - Is the async code correct and efficient?
- **Retry logic** - Is the retry implementation robust?
- **Streaming** - Is the SSE (Server-Sent Events) parsing correct?

## Time Allocation

- Environment verification: 2-3 min
- Code review & bug identification: 10-15 min
- Fixing bugs: 15-20 min
- Discussion & verification: 10 min
